01 / Product problem

Paper trading should explain decisions, not only replay prices.

Many simulation products focus on order entry and portfolio value. ThePnLab was designed around the broader decision loop: screening, portfolio state, position sizing, execution, risk monitoring, and post-decision explanation.

02 / Architecture

A modular full-stack system.

Market data→Decision cycle→Execution→Portfolio state→Coach
  • FastAPI routers separate authentication, market, portfolio, replay, bot, and coaching concerns.
  • PostgreSQL models persist users, portfolios, positions, and operational state.
  • A React frontend organizes market, portfolio, leaderboard, replay, and settings workflows.
  • Tests cover authentication, schedules, portfolio behavior, margin logic, derivatives, and system metrics.
03 / Portfolio and risk logic

Positions are modeled as constrained state, not isolated trades.

The backend includes portfolio accounting, position lifecycle, margin and liquidation logic, overnight handling, and take-profit / stop-loss monitoring. This makes the application a systems project as much as a user-interface project.

Simulation boundary

ThePnLab is an educational paper-trading product. It does not execute real-money orders and should not be interpreted as investment advice.

04 / Explainable coaching

A retrieval-assisted layer turns system state into feedback.

The coaching layer combines portfolio context with a curated knowledge base to explain decisions and surface learning points. The design goal is traceability: feedback should be linked to observable state and documented concepts rather than presented as an opaque recommendation.
